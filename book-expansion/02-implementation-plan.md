# Mere fra bogen – implementeringsplan (trin 2 af 3)

This is the build plan for stage 3. The builder (Haiku 5.5) follows it **literally**, step by step. Every design decision is already made here. If something in the repo does not match what this plan says, **stop and ask** instead of improvising.

Sources: `book-expansion/01-content-plan.md` (section 5 = placement rules) and `book-expansion/01-content-plan.json` (the 372 excerpts). This plan was dry-run on a scratch copy of the site: every **Find** block below matched exactly once, the build ran, and the checks passed.

## 0. Rules for the builder

1. Work on a new branch `book-expansion`, made from `main` (step 1). Do all work in the repo folder `/Users/moustafasamhoury/StudioProjects/medborgerskabsproven`.
2. **Do not push. Do not merge. Do not open a PR.** One local commit at the end (step 12). The user decides about pushing.
3. Change only the files in the table below. Do not touch `bookdump/`, `data/questions.json`, `data/clusters.json`, `data/topics.json`, `data/fact_groups.json`, any `.html` file, or anything in `book-expansion/` (except running its scripts).
4. **Never change excerpt text.** `data/book_more.json` is a byte-for-byte copy of `book-expansion/01-content-plan.json`. Do not reformat, re-indent, translate, "fix" typos, or remove the `*` marks.
5. Make every code change with the Edit tool: `old_string` = the **Find** block, `new_string` = the **Replace with** block, both copied exactly (spaces included). Each Find block occurs exactly once in its file. If an Edit fails with "not found" or "not unique", stop and report; do not guess.
6. Run the checkpoint command after each step. If it does not give the expected result, stop and report the output.
7. All page text goes in through `h()` / text nodes (as in the rest of `js/ui.js`). Never use `innerHTML` for data.
8. If `git status` at step 1 shows modified **tracked** files, stop and ask (another session may be working in this folder). Untracked files (`*_PLAN.md`, `HANDOVER.md`, `book-expansion/`) are expected; leave them alone.

## 1. What gets built (summary)

- **Data:** `data/book_more.json` (copy of the content plan JSON) → `tools/build_data.py` puts it into `data/bundle.js` as `more` → `js/data.js` exposes it as `MBP.data.more` (`{id: [{title_da, page, lines, excerpt_da}]}`; id = cluster id, fact-group id `fg-…` or topic id). The fetch fallback in `js/data.js` also loads it.
- **Feedback after every answer** (most important): `explainPanel` in `js/ui.js` gets `<details class="book-more book-more-feedback" open>` with summary «Mere fra bogen (N)», showing every excerpt of `MBP.data.more[q.cluster_id]`. It stands after the notes / answer-key note and before «Stillet i …» and «Næste». Same for verdict `true`, `false` and `null`. One component covers Test (normal), the exam hand-in review and Øv, because all of them use `MBP.ui.questionCard` → `explainPanel`. Open by default; if the reader closes it, it stays closed for the next answers (`localStorage` key `mbp.v1.bookMoreOpen`, via `MBP.store`).
- **Book popover section 2:** the existing «Læs mere i bogen» popover gets a second section «Mere fra bogen» with the extra excerpts, on: Læs fact rows (cluster), Læs fact groups (group), Øv lesson cards and the Øv recap (cluster), Top 15 (cluster). A book button with extra excerpts gets a small dot (`.book-btn.has-more`) and a longer aria-label.
- **No duplication:** the book button **inside the feedback** gets no `more` (section 1 only), because the same excerpts already stand inline in the feedback block. Topic intro paragraphs and notes get no `more` either.
- **End of each Læs topic:** a closed `<details class="book-more">` «Mere fra bogen (N)» with the topic-level excerpts (`MBP.data.more[topic.id]`), before the end bar.
- **Check script:** `tools/check_book_more.js` (copied from `book-expansion/check_bundle_more.js`) loads `data/bundle.js` in node and asserts: `more` equals `data/book_more.json` and `01-content-plan.json` exactly, keys are real ids, items are well-formed, and **every question's `cluster_id` has `more` content (500/500)**.

### Danish / English UI strings (exact)

| Where | Danish | English (`.en` span via `bi()`) |

| Popover section 2 heading | `Mere fra bogen` | `More from the book` |

| Glossary note (once, only if an excerpt contains `*`) | `* = forklaret i bogens ordliste, s. 147–155` | `* = explained in the book's glossary` |

`N` = number of excerpts. «afsnit» is the same in singular and plural.

```js
  // "Åbn side N i bogen": the link to the page in the PDF served with the site.
  function pageLink(page) {
    return h("p", { class: "book-links" },
      h("a", { href: BOOK_PDF + "#page=" + page, target: "_blank", rel: "noopener" },
        MBP.icon("open", 16), bi("Åbn side " + page + " i bogen", "Open page " + page + " in the book (PDF)", "span")));
  }

  // ---------- "Mere fra bogen": extra book excerpts (data/book_more.json) ----------

  // The extra excerpts for a cluster, fact-group or topic id, in display order ([] when there are none).
  function moreFor(id) {
    return (MBP.data && MBP.data.more && MBP.data.more[id]) || [];
  }

  // The excerpt text, word for word: the text before the first "•" is a paragraph, each "•" item a list item.
  function moreText(text) {
    var parts = text.split("•").map(function (s) { return s.trim(); });
    var intro = parts.shift();
    var items = parts.filter(Boolean);
    return [
      intro ? h("p", null, intro) : null,
      items.length ? h("ul", { class: "book-more-list" }, items.map(function (s) { return h("li", null, s); })) : null
    ];
  }

  // One extra excerpt: its heading, the citation, the quote and the link to the page.
  function moreItem(x) {
    return h("section", { class: "book-ref book-more-item" },
      h("h4", { class: "book-more-title", lang: "da" }, x.title_da),
      h("p", { class: "book-cite" }, "Læremateriale 2026 · " + refLabel(x)),
      h("blockquote", { class: "book-quote", lang: "da" }, moreText(x.excerpt_da)),
      pageLink(x.page));
  }

  // "* = explained in the glossary", once, when one of the excerpts has a "*".
  function starNote(items) {
    var any = items.some(function (x) { return x.excerpt_da.indexOf("*") !== -1; });
    return any ? h("p", { class: "book-more-star" },
      bi("* = forklaret i bogens ordliste, s. 147–155", "* = explained in the book's glossary", "span")) : null;
  }

  // Section 2 of the book popover.
  function moreSection(more) {
    return h("div", { class: "book-more-pop" },
      h("h3", { class: "book-more-head" }, bi("Mere fra bogen", "More from the book", "span")),
      more.map(moreItem),
      starNote(more));
  }

  // "Mere fra bogen (N)" as an inline block. Returns null when there are no excerpts.
  // opts.feedback: the block in the feedback after an answer (open unless the reader closed it; the choice is kept).
  // Without it: the closed block at the end of a topic in Læs.
  function moreBlock(items, opts) {
    if (!items || !items.length) return null;
    var feedback = !!(opts && opts.feedback);
    var chev = MBP.icon("next", 16);
    chev.classList.add("book-more-chev");
    var block = h("details", {
      class: feedback ? "book-more book-more-feedback" : "book-more",
      open: feedback && MBP.store.bookMoreOpen()
    },
      h("summary", null, chev,
        bi("Mere fra bogen (" + items.length + ")", "More from the book (" + items.length + ")", "span")),
      h("div", { class: "book-more-body" }, items.map(moreItem), starNote(items)));
    if (feedback) {
      block.addEventListener("toggle", function () { MBP.store.setBookMoreOpen(block.open); });
    }
    return block;
  }
```
